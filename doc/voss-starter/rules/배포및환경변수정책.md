# 배포및환경변수정책

## 1. GitLab / CI/CD 기본 원칙

- 이 프로젝트는 자체 GitLab 저장소와 GitLab 기반 CI/CD를 사용합니다.
- `.gitlab-ci.yml`은 서버 담당자가 관리하는 공통 배포 설정 파일이므로 직접 수정 전제로 해결하지 않습니다.
- `Dockerfile`과 `.dockerignore`는 프로젝트 저장소 최초 생성 시에만 권장 초기 파일로 제공되며, 이후에는 프로젝트 사용자가 직접 관리합니다.
- VOSS의 기존 저장소 동기화는 `Dockerfile`과 `.dockerignore`를 수정하거나 덮어쓰지 않습니다.
- 배포 문제가 있더라도 `.gitlab-ci.yml` 수정으로 해결하지 않습니다.
- 배포 완료 콜백처럼 CI 변경이 필요하면 `.gitlab-ci.yml`을 직접 고치지 말고 서버 담당자에게 필요한 변경 요청 내용을 전달합니다.

## 2. 우선 검토해야 하는 해결 방식

- `package.json` 수정
- 환경 변수 추가 또는 정리
- 앱 런타임 설정 수정
- `scripts/` 추가
- 문서 보완

CI/CD를 깨뜨릴 수 있는 변경은 반드시 사전 검토 후 진행합니다.

## 3. 환경변수 추가 시 반드시 함께 남길 내용

새 환경변수가 필요하다고 판단하면, 코드에 환경변수 이름만 추가하고 끝내지 않습니다. 반드시 아래를 함께 문서화하거나 개발자에게 전달합니다.

- 필요한 환경변수 이름
- 어디에 설정해야 하는지
  - 프로젝트 환경설정 탭
  - 서버 기본 환경변수
  - GitLab CI/CD Variables
- 설정되지 않으면 어떤 문제가 발생하는지
  - 빌드 실패
  - 런타임 500 오류
  - 외부 API 인증 실패
  - 로그인 / OTP / 텔레그램 기능 불가

## 4. 배포 전후 확인 항목

- 빌드 단계와 런타임 단계에서 필요한 환경변수를 구분했는지
- 새 비밀값이 하드코딩되지 않았는지
- 배포 후 실제 서비스 반영 지연이나 상태 확인 방식을 사용자에게 안내해야 하는지
- 하네스와 정합성 점검 결과를 남겼는지
- 배포 후 현재 운영 버전에 대한 AI 보안 점검과 제출 계획을 정했는지
