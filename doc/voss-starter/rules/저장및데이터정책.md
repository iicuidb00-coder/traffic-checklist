# 저장및데이터정책

## 1. 저장 방식 선택

### 소규모 프로젝트

- JSON 기반 로컬 저장을 허용할 수 있습니다.
- 파일 저장 시 동시 접근, 무결성, 백업 가능성을 함께 고려합니다.
- 서비스에서 지속 보관할 구조화 데이터는 PostgreSQL 사용을 우선 검토합니다.

### 중규모 이상 프로젝트

- VOSS 제공 PostgreSQL 사용을 우선 검토합니다.
- 가능하면 Prisma 사용을 우선 검토합니다.
- 스키마, 마이그레이션, 초기화 기준을 함께 설계합니다.

## 2. 공통 데이터 설계 규칙

- DB 접근은 Repository / Service 계층으로 분리합니다.
- UI, Route, Action에서 직접 DB 호출 로직을 난립시키지 않습니다.
- 상태 전이와 저장 흐름은 문서와 구현이 일치해야 합니다.
- 삭제, 정지, 승인, 배포 같은 상태 변경은 문서에 전이 조건과 후속 효과를 함께 남깁니다.
- 외부 연동 키, 토큰, 비밀값은 일반 설정값과 구분해 저장하고 마스킹 규칙을 함께 고려합니다.

## 3. 데이터 변경 시 함께 확인할 항목

- 어떤 데이터가 생성, 수정, 삭제되는지
- 실패 시 롤백 또는 재시도 기준이 무엇인지
- 권한에 따라 조회 범위나 수정 가능 범위가 달라지는지
- 로그, 감사 이력, 알림과 연계되는지
