- `rules/문서관리규칙.md`

## 작업 문서

- 기획: `plans/`
- 설계: `design/`
- 구현: `implementation/`
- 검증: `testing/`
  - 하네스 검사: `testing/하네스검사_템플릿.md`
  - 정합성 점검: `testing/정합성점검_템플릿.md`

## 문서 사용 순서

1. 현재 작업 목적과 배경은 `status/현재진행상태.md`에 기록합니다.
2. 공통 문서 운영 원칙은 `rules/문서관리규칙.md`에서 확인합니다.
3. 기술 스택과 구현 제한은 `rules/기술기준.md`에서 확인합니다.
4. 저장 방식과 상태/데이터 설계 원칙은 `rules/저장및데이터정책.md`에서 확인합니다.
5. 배포, CI/CD, 환경변수 관련 제약은 `rules/배포및환경변수정책.md`에서 확인합니다.
6. 실제 작업은 `plans/`, `design/`, `implementation/`, `testing/` 순서로 진행합니다.
7. 운영에 반영한 버전은 배포 후 `../VOSS_AI통합보안점검.md`과 `../tools/security_scan.py`로 보안 점검하고 원본 파일을 남깁니다.
8. VOSS 공식 이력이 필요하면 원본 파일을 확정한 뒤 보안 점검 탭에서 제출 토큰을 발급해 바로 제출합니다.

## 문서 추가 원칙

- 위 문서가 기본 시작점입니다.
- 기능 특성상 더 필요한 문서가 있으면 새 문서를 추가하되, 같은 목적의 문서를 중복 생성하지 않습니다.
- 보안, 릴리즈, ADR 문서가 필요하면 현재 작업 문서에서 연결을 남기고 별도 경로를 만들어 관리합니다.
